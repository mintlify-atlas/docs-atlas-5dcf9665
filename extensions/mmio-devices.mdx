MMIO (Memory-Mapped I/O) plugin devices let you place custom peripherals anywhere in Spike's physical address space. You implement the `abstract_device_t` interface, compile a shared library, register the factory in the global device map, and attach the device at startup with `--device`. No simulator rebuild is required.

## The `abstract_device_t` interface

All MMIO devices inherit from `abstract_device_t`, declared in `riscv/abstract_device.h`:

```cpp
class abstract_device_t {
 public:
  // Called by the memory bus for load (read) accesses
  virtual bool load(reg_t addr, size_t len, uint8_t* bytes) = 0;

  // Called by the memory bus for store (write) accesses
  virtual bool store(reg_t addr, size_t len, const uint8_t* bytes) = 0;

  // Return the size (in bytes) of this device's address region
  virtual reg_t size() = 0;

  virtual ~abstract_device_t() {}

  // Optional: called every RTC tick for devices that need periodic updates
  virtual void tick(reg_t rtc_ticks) {}
};
```

### Method reference

#### `load(addr, len, bytes)`

Called when the processor reads from the device's address range. `addr` is the offset from the device's base address. Copy `len` bytes of response data into `bytes`. Return `true` on success, `false` to signal a bus error.

#### `store(addr, len, bytes)`

Called when the processor writes to the device's address range. `addr` is the offset from the device's base address. The `len` bytes to write are in `bytes`. Return `true` on success, `false` to signal a bus error.

#### `size()`

Returns the number of bytes this device occupies on the memory bus. Spike uses this to bound the device's address region.

#### `tick(rtc_ticks)`

An optional periodic callback. Spike's simulation loop increments an RTC counter and calls `tick()` on all registered devices. Use this for devices that must update internal state independently of CPU accesses (e.g., timers, UARTs draining their FIFOs).

## The `device_factory_t` interface

To allow `--device` to instantiate your peripheral, implement the `device_factory_t` interface:

```cpp
class device_factory_t {
 public:
  // Parse device tree (FDT) node and instantiate the device.
  // Sets *base to the device's base address on the memory bus.
  // sargs contains any extra arguments from --device=<name>,<arg1>,<arg2>,...
  virtual abstract_device_t* parse_from_fdt(
      const void* fdt,
      const sim_t* sim,
      reg_t* base,
      const std::vector<std::string>& sargs) const = 0;

  // Generate a DTS node string for this device (used by --dump-dts)
  virtual std::string generate_dts(
      const sim_t* sim,
      const std::vector<std::string>& sargs) const = 0;

  virtual ~device_factory_t() {}
};
```

## The global device registry

```cpp
using mmio_device_map_t = std::map<std::string, const device_factory_t*>;
mmio_device_map_t& mmio_device_map();
```

`mmio_device_map()` returns a reference to the process-global registry that maps device name strings to factory instances. Spike looks up `--device=<name>` entries in this map at startup.

## The `REGISTER_DEVICE` macro

The `REGISTER_DEVICE` macro, also in `riscv/abstract_device.h`, is the easiest way to register a factory. It generates a factory subclass and a global instance whose constructor inserts the entry into `mmio_device_map()`:

```cpp
#define REGISTER_DEVICE(name, parse, generate) \
  class name##_factory_t : public device_factory_t { \
  public: \
    name##_factory_t() { \
      std::string str(#name); \
      if (!mmio_device_map().emplace(str, this).second) \
        throw std::runtime_error("Plugin \"" + str + "\" already registered"); \
    } \
    name##_t* parse_from_fdt(const void* fdt, const sim_t* sim, \
                              reg_t* base, \
                              const std::vector<std::string>& sargs) const override \
      { return parse(fdt, sim, base, sargs); } \
    std::string generate_dts(const sim_t* sim, \
                              const std::vector<std::string>& sargs) const override \
      { return generate(sim, sargs); } \
  }; \
  device_factory_t* name##_factory = new name##_factory_t();
```

Usage:

```cpp
REGISTER_DEVICE(my_device, my_device_parse, my_device_generate_dts)
```

<Note>
Registering a name that is already in the map throws a `std::runtime_error`. Each device name must be globally unique across all loaded shared libraries.
</Note>

## How devices appear on the memory bus

Spike manages all memory and devices through a `bus_t` instance (itself an `abstract_device_t`) that owns an ordered map from base address to device pointer. When a processor performs a load or store, `bus_t` finds the device whose region contains the address and calls its `load()` or `store()` method.

The `sim_t` class exposes:

```cpp
void sim_t::add_device(reg_t addr, abstract_device_t* dev);
```

Spike calls this internally after instantiating each plugin device via its factory's `parse_from_fdt()`. The `base` output parameter of `parse_from_fdt()` tells Spike the physical address at which to mount the device.

## Building and loading a plugin device

<Steps>

### Implement `abstract_device_t` and `device_factory_t`

Create a `.cc` file containing:
- Your device class inheriting from `abstract_device_t`
- A `parse_from_fdt()` function that instantiates and configures it
- A `generate_dts()` function that produces a DTS node string
- A `REGISTER_DEVICE(...)` call at file scope

```cpp
#include "abstract_device.h"
#include <cstring>
#include <string>
#include <vector>

class my_device_t : public abstract_device_t {
 public:
  my_device_t(reg_t base_addr) : base(base_addr) {
    memset(regs, 0, sizeof(regs));
  }

  bool load(reg_t addr, size_t len, uint8_t* bytes) override {
    if (addr + len > sizeof(regs)) return false;
    memcpy(bytes, regs + addr, len);
    return true;
  }

  bool store(reg_t addr, size_t len, const uint8_t* bytes) override {
    if (addr + len > sizeof(regs)) return false;
    memcpy(regs + addr, bytes, len);
    return true;
  }

  reg_t size() override { return sizeof(regs); }

 private:
  reg_t base;
  uint8_t regs[0x1000];
};

static my_device_t* my_device_parse(
    const void* fdt, const sim_t* sim,
    reg_t* base, const std::vector<std::string>& sargs)
{
  *base = 0x40000000;  // mount at a fixed physical address
  return new my_device_t(*base);
}

static std::string my_device_generate_dts(
    const sim_t* sim, const std::vector<std::string>& sargs)
{
  return "my_device@40000000 { compatible = \"my_device\"; "
         "reg = <0x0 0x40000000 0x0 0x1000>; };\n";
}

REGISTER_DEVICE(my_device, my_device_parse, my_device_generate_dts)
```

### Compile as a shared library

```bash
g++ -std=c++17 -fPIC -shared \
    -I/path/to/riscv-isa-sim \
    -I/path/to/riscv-isa-sim/riscv \
    -o my_device.so my_device.cc
```

### Load the library and attach the device

```bash
# Load the library and attach the device by name
spike --extlib=./my_device.so \
      --device=my_device \
      pk my_program

# Pass extra arguments to parse_from_fdt via sargs
spike --extlib=./my_device.so \
      --device=my_device,0x40000000,4096 \
      pk my_program
```

</Steps>

## Spike command-line options

| Option | Description |
|--------|-------------|
| `--extlib=<path>` | Load a shared library (`.so`). May be repeated for multiple libraries. |
| `--device=<name>` | Attach the named device from a previously loaded `--extlib`. May be repeated. |
| `--device=<name>,<arg1>,<arg2>,...` | Pass additional string arguments to the device's `parse_from_fdt()` via `sargs`. |
| `--dtb-discovery` | Discover devices from an externally provided device tree blob instead of using `--device`. |
| `--dump-dts` | Print the generated device tree string and exit. Useful for verifying `generate_dts()`. |

## Device tree discovery with `--dtb-discovery`

As an alternative to `--device`, Spike supports discovering MMIO plugin devices directly from a device tree blob (DTB):

```bash
spike --dtb=my_board.dtb --dtb-discovery pk my_program
```

<Warning>
`--dtb-discovery` is **incompatible** with the `-m` memory layout option and with `--device`. Do not mix these flags. When `--dtb-discovery` is active, Spike reads all memory regions and device placements from the supplied DTB rather than from command-line arguments.
</Warning>

Device entries in the DTS must include a `spike_plugin_params` field recognized by Spike's DTB discovery logic, which calls `parse_from_fdt()` on each matching factory to instantiate and mount the device.
